# 5.2 Performance Assurance Engine — KPI Computation (implemented)

Implemented in `roaming-analysis-service`. Computes windowed roaming KPIs per **Roaming Agreement**
(partner / visited operator), evaluates them against SLA thresholds with consecutive-window
alarming, maintains a rolling performance score used for steering-tier adjustment, and runs a
synthetic (IREG-style) test-call scheduler.

## Streaming aggregation windows
`domain/KpiWindow` — **FIVE_MIN** (real-time), **HOUR**, **DAY**, **MONTH** (billing-aligned,
calendar-exact). `truncate()` buckets an event timestamp; `next()` gives the following boundary.
Because the dataset is historical, "now" = the most recent event timestamp in the loaded data.

## Core KPI formulas (`analysis/KpiCalculator`)
| KPI | Formula | Source fields |
|-----|---------|---------------|
| Registration Success Rate | successful attaches / total attempts × 100 | `attach_events.attach_status` (`success`/`failure`) |
| ASR (Answer Seizure Ratio) | answered voice / voice attempts × 100 | voice `roaming_cdrs.duration_seconds` > 0 |
| NER (Network Efficiency Ratio) | calls with a valid network response / attempts × 100 | voice `call_end_datetime` present (≥ ASR) |
| ACD (Average Call Duration) | Σ answered duration / answered calls | `duration_seconds` |
| Session Setup Success Rate | non-dropped established / total × 100 | `session_qos.session_status` |
| Average Latency + P50/P95/P99 | mean + nearest-rank percentiles | `session_qos.latency_ms` |
| Drop Rate | dropped / established × 100 | `session_qos.session_status` = `dropped` |
| Throughput (data) | Σ(download+upload)MB × 8 / Σ active-session seconds → Mbps | `download_mb`,`upload_mb`, session times |

**Honest data proxies** (the CDR dataset has no explicit call-outcome codes):
ASR "answered" = positive duration; NER "valid response" = a call-end timestamp exists; session
setup success is complementary to drop rate (no explicit setup-failure rows in `session_qos`).
These are documented in the calculator's Javadoc and are the clean seam to replace with real
outcome codes / 5G-SBI signalling later.

## SLA evaluation logic (`service/PerformanceAssuranceService`)
1. Per completed window, compute the KPI set per `Roaming_Agreement_Ref` (partner).
2. Compare against the agreement's `SLA_KPIs` thresholds (`domain/RoamingAgreement`).
3. **Alarm** when a breach persists for **N consecutive windows**
   (`roaming.sla.alarm-consecutive-windows`, default **3**).
4. Fold each window into the agreement's **rolling performance score** (EWMA) → derives the steering
   **tier** (PREFERRED / STANDARD / PROBATION / RESTRICTED) that the Steering Protection Engine reads.

The **streaming tick** (`@Scheduled`, `roaming.sla.tick-ms`, default 5 min) evolves the rolling
score; the `/sla` endpoint is a **read-only** evaluation that never mutates state.

## Synthetic test-call scheduler
`runSyntheticTests()` executes IREG-style probes (REGISTRATION, MO_CALL, MT_CALL, SMS, DATA_SESSION)
per active agreement, biased by the agreement's current health. Results are flagged
`sessionType = "Synthetic_Test"` and **never written to the live repositories**, so they are excluded
from live KPI denominators by construction.

## API (added to `/api/roaming`, all `PERM_roaming-events:read`)
| Method | Path | Purpose |
|--------|------|---------|
| GET | `/kpis?partner=&window=` | KPI set for the latest completed window (`window` = FIVE_MIN·HOUR·DAY·MONTH; `partner` optional → all) |
| GET | `/kpis/timeseries?partner=&window=&count=` | KPI set across the last N windows (trend/reporting) |
| GET | `/agreements` | Per-partner SLA thresholds + rolling score + tier |
| GET | `/sla?window=` | Per-agreement SLA evaluation: breaches, consecutive count, alarm, score, tier (worst first) |
| POST | `/test-calls/run` | Run synthetic IREG test transactions |

Reachable via the gateway at the same paths (wildcard `/api/roaming/**`); Swagger aggregated under
`/roaming-analysis-service/v3/api-docs`.

## Configuration
| Property | Default | Meaning |
|----------|---------|---------|
| `roaming.sla.alarm-consecutive-windows` | `3` | consecutive breached windows → alarm |
| `roaming.sla.tick-ms` | `300000` | streaming rolling-score tick period (ms) |
